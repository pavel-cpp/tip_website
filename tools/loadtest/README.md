# Нагрузочные тесты TIP

Скрипты Node (22+) бьют по работающему экземпляру через настоящий API и WebSocket: создают проект на 5000 строк и
учётные записи `lt-*`, гоняют «операторов» (вход, открытие проекта целиком, комната, блокировка строки, PATCH, курсор)
и всё убирают за собой. Клиентская латентность включает сеть до сервера; серверную смотрите в Prometheus
(`tip_http_request_duration_seconds`, `tip_db_in_use`) и по `docker stats`.

```bash
cd tools/loadtest && npm install            # единственная зависимость: ws (глобальный WebSocket не умеет Origin)
export TIP_BASE=https://tip.example.ru TIP_STATE=/tmp/lt-state.json
export TIP_ADMIN_LOGIN=... TIP_ADMIN_PASSWORD=...

node setup.mjs 40 5000                      # проект LOADTEST и 40 операторов
TIP_STAGGER=15 node phase.mjs 40 45         # 40 операторов, 45 с, входят в течение 15 с
TIP_SESSIONS=2 node phase.mjs 40 45         # 80 сессий (по две на учётку)
node burst.mjs 10 3                         # 10 операторов одновременно открывают проект (список на 5000 строк)
node soak.mjs 400 30                        # 400 простаивающих WebSocket на 30 с
node teardown.mjs                           # удаляет проект и деактивирует учётки
```

`phase.mjs` завершается с кодом 2, если p95 PATCH выше 2 с или были ответы 5xx. Учётки API удалить не умеет:
после `teardown.mjs` их можно стереть SQL (`delete from users where login like 'lt-%'`).

Не запускайте против сервера, на котором работают люди: при 100 операторах запросы начинают ждать.

## Результаты прод-сервера (2 vCPU, 2 ГБ, tipd mem_limit 96 МБ), 14.11.2026

Сеть до сервера из тестовой машины ≈ 115 мс на запрос. Оператор правит строку примерно раз в 1,5 с.

| Одновременно правят | PATCH p50 / p95, мс | tipd CPU пик | tipd память пик | Итог |
|---|---|---|---|---|
| 5 | 136 / 148 | 7 % | 32 МБ | ровно |
| 20 | 174 / 285 | 113 % | 77 МБ | ровно |
| 40 | 117 / 315 | 65 % | 71 МБ | ровно |
| 60 (3 минуты) | 124 / 190 | 80 % | 79 МБ | стабильно, память вернулась к 25 МБ |
| 80 | 129 / 392 | 98 % | 79 МБ | предел комфорта, load average 3,4 на 2 ядра |
| 102 | 178 / 2186 | 99 % (Caddy 147 %) | 81 МБ | деградация: открытие проекта до 19 с |

Остальное: 400 простаивающих WebSocket держатся без роста памяти; 24 входа в секунду; полное открытие проекта на
5000 строк — 1 МБ JSON, 15 одновременных открытий дают p50 3,5 с (упирается в сжатие в Caddy).

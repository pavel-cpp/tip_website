## 2. Стек и структура

Vite + React + TypeScript (strict). Маршрутизация — React Router. Серверное состояние — TanStack Query
(кэш, ретраи, инвалидация). Таблица — TanStack Virtual (рендерим ~30 строк из 5 000). Типы и клиент API — из `backend/api/openapi.yaml` (`openapi-typescript`); Swagger UI — `/api/docs`.
Стили — CSS с токенами (`tokens.css` из демо), без UI-фреймворка (меньше JS, полный контроль над темами (тёмная — по умолчанию, светлая — опционально)).
Строки — словарь `i18n/ru.ts` (Q8). Линтер/форматтер — Biome.

```
frontend/src/
  api/        # клиент (fetch + generated types), query-хуки, ws-клиент (reconnect, resync)
  auth/       # хранилище access-токена (в памяти), refresh-логика, guards по правам (`perms` из токена/`/me`)
  components/ # Avatar, Menu, Modal, Toast, Table, Panel, Icon …
  lib/        # renderTicket, print, clipboard, zip, platform (определение iOS/Mac)
  pages/      # Login, Projects, Workspace, ProjectSettings, Profile, admin/*
  styles/     # tokens.css, base.css, ui.css
  i18n/
```

## 4. Адаптивность

| Ширина | Раскладка рабочего пространства |
|---|---|
| ≥ 1100 px | Две панели рядом (как в макете) |
| 860 px и шире, альбомная ориентация (планшет) | Две панели рядом |
| 700–1099 px (кроме альбомного планшета) | Панели друг под другом, высота делится, можно свернуть одну |
| < 700 px и альбомный телефон (высота ≤ 500 px) | **Табы** «Картинка / База»; строка таблицы — карточка (№, имя и телефон полностью); правка — нижний sheet с предпросмотром билета; тулбар — нижняя панель «Печать (N)» + меню «⋯». В режиме выбора (долгое нажатие) панель действий **заменяет** нижний тулбар на месте и не перекрывает список; «Выбрать все» и счётчик — в шапке списка |

* Единицы `dvh/svh` вместо `vh`; `viewport-fit=cover` и `env(safe-area-inset-*)` для выреза и «домашней полоски».
* Цели касания ≥ 44×44 px; `@media (hover: hover)` для hover-эффектов (нет «залипания» на touch).
* Поля ввода ≥ 16 px (иначе iOS приближает страницу при фокусе).
* `prefers-reduced-motion`, `color-scheme: dark`, видимый `:focus-visible`.
* Страница настроек проекта: на телефоне превью липкое под верхней панелью, панель «Отмена / Сохранить» закреплена внизу; панели не перехватывают прокрутку страницы. Тосты показываются сверху, под верхней панелью, чтобы не закрывать подвалы, панели сохранения и нижний тулбар.
* Потеря связи: баннер «Нет связи — изменения сохранятся автоматически, как только она появится» накладывается поверх шапки без сдвига страницы, срабатывает по событию `offline` и по отсутствию `pong` в течение 10 с; у строк с неотправленной правкой — метка «Не отправлено».

## 5. Подводные камни macOS/iOS и решения

| # | Проблема | Решение |
|---|---|---|
| 1 | `localStorage` на iOS очищается ITP через 7 дней неактивности, а токен в нём доступен XSS | Access-JWT — **только в памяти**; при загрузке страницы SPA получает его через `POST /auth/refresh` (refresh-cookie `HttpOnly; SameSite=Strict`, ITP её не режет — она выставлена сервером). Автообновление за ~1 мин до `exp` и один повтор запроса после `401 TOKEN_EXPIRED`; параллельные запросы и вкладки ждут один общий refresh (`navigator.locks`, Safari ≥ 15.4); повтор refresh в течение 10 с сервер обрабатывает идемпотентно. `localStorage` — только для UI-мелочей (свёрнутые панели) с try/catch |
| 2 | Лимит canvas ~16,7 Мпикс / память | Картинка проекта ≤ 4096 px по длинной стороне (уменьшение при загрузке); пакетный рендер последовательно, `canvas.width = 0` после использования |
| 3 | Safari рисует fallback-шрифт, если веб-шрифт не загружен | Шрифты self-host (`@fontsource`, подмножество cyrillic+latin, `font-display: swap`); перед рендером `document.fonts.load()` для каждого плейсхолдера. «Arial» из демо → «Arimo» (метрически совместим) |
| 4 | `navigator.clipboard.write` требует жеста пользователя; Safari ждёт Promise в `ClipboardItem` | `new ClipboardItem({'image/png': renderPromise})` прямо в обработчике клика/⌘C; запасной путь — модалка с картинкой («удерживайте для копирования») |
| 5 | Горячая клавиша копирования: Ctrl+C vs ⌘C | Обрабатываем `metaKey` на Mac/iOS; подсказка в тулбаре («Копировать — ⌘C» / «Ctrl+C») определяется по платформе |
| 6 | iOS блокирует серию программных скачиваний | Несколько файлов → один **ZIP** (`fflate`), один файл → PNG; на iOS — `navigator.share({files})` как предпочтительный путь |
| 7 | `window.print()` из скрытого iframe нестабилен на iOS | Билеты рендерятся в скрытые листы A4 прямо в рабочем месте (CSS `@page`, сетка билетов 7×4 см, правила только в `@media print`, остальное приложение при печати скрыто) + `window.print()`; отдельной страницы нет, отмена диалога оставляет пользователя на месте; на iOS печать запускается кнопкой в тосте; запасной путь — PDF (спайк в Фазе 4, кандидат `pdf-lib`) |
| 8 | Safari закрывает WS в фоне, bfcache | Слушаем `visibilitychange`/`pageshow(persisted)` → reconnect + resync; локи с TTL |
| 9 | HEIC с iPhone | `<input type="file" accept="image/png,image/jpeg">` — iOS сам конвертирует в JPEG; сервер HEIC не принимает |
| 10 | Перетаскивание плейсхолдеров на touch | Pointer Events + `touch-action: none` на плейсхолдере; пинч/скролл страницы не конфликтуют; координаты — в пикселях исходной картинки |
| 11 | Менеджеры паролей / iCloud Keychain | Корректные `autocomplete="username"`, `current-password`, `new-password`, `name`/`id` |
| 12 | Resize-эффекты клавиатуры iOS | `visualViewport` для sheet-редактора; `interactive-widget=resizes-content` |
| 13 | Rubber-band скролл ломает панели | `overscroll-behavior: contain` на скролл-контейнерах |
| 14 | Нет `showSaveFilePicker` в Safari | Скачивание через `<a download>`/share, не File System Access API |

Фичи, которые **не** используем из-за поддержки: File System Access API, Web Serial/USB, `OffscreenCanvas`-зависимость без fallback.
PWA: `manifest.webmanifest` + иконки для «На экран Домой» (service worker/офлайн — вне v1).

## 6. Рендер билета

Один модуль `renderTicket` для превью, копии, сохранения и печати (WYSIWYG, как в демо).
Координаты (x, y) — центр текста в пикселях исходной картинки; шрифт/размер/обводка/цвет/начертание — из `project_placeholders`.
**Печать — как в десктопе (константа, не настройка проекта):** билет **7×4 см** (70×40 мм); билеты укладываются плотно слева направо, затем вниз, при заполнении листа — новая страница;
зазор между билетами ≈ 0,5 мм (в десктопе — 10 пикселей принтера), поля листа нулевые (`@page { size: A4; margin: 0 }`), изображение растягивается на рамку билета (`object-fit: fill`, как `drawPixmap` в Qt).
На A4 помещается 3×7 = **21 билет**. Печатаются только выбранные строки; после диалога печати — запись в аудит (состояние строк не меняется). Константы живут в `lib/print.ts`.
Нюансы, унаследованные от десктопа: у большинства принтеров есть непечатаемые поля 3–5 мм, и крайний билет в ряду может слегка обрезаться — в диалоге печати браузера выбираем «Масштаб 100 %, без полей»;
при загрузке картинки проекта UI подсказывает рекомендуемое соотношение сторон **7:4** (иначе изображение растянется, как и в десктопе).
Большие партии рендерятся последовательно с индикатором прогресса (не блокируя UI), максимум N одновременных canvas.

## 7. Таблица участников

* Виртуализация, фиксированная высота строки, `role="grid"`, навигация стрелками/Tab/Enter, Esc отменяет правку.
* Мультивыбор: Shift/⌘/Ctrl + клик; «выделить все видимые».
* Поиск по имени/телефону — на клиенте по загруженным строкам (мгновенно, без запросов).
* **Колонки: №** (порядковый номер), **Имя**, **Номер телефона** — больше ничего, статуса нет.
* **Блокировка строки:** пока коллега правит строку, она блокируется — поля недоступны для ввода, строка аккуратно обводится **цветом этого пользователя** (рамка 2 px, скругление, мягкое свечение),
  а при наведении появляется подсказка «Редактирует <имя>» с его аватаром. На touch-устройствах (нет hover) подсказка открывается по касанию строки. Попытка начать правку занятой строки — лёгкая «встряска» рамки и та же подсказка.
  Блокировка снимается сразу при blur/Esc/Enter, при разрыве соединения и по TTL 45 с. Собственная редактируемая строка подсвечивается вашим цветом.
* **Курсоры коллег** (просто «смотрят на строку») — тонкая цветная метка у номера строки, без обводки и блокировки, чтобы не путать с редактированием.
* Правка ячейки: `lock.acquire` → ввод → `PATCH` с `version` → `lock.release`. Конфликт → подсветка и предложение принять чужое значение/повторить.
* Оптимистичные обновления TanStack Query с откатом при 409/ошибке.

## 10. UX, анимации и интерактивность

Требование: интерфейс **красивый, плавно анимированный, с приятной интерактивностью и при этом интуитивно простой** — оператор, впервые открывший систему, должен без инструкции дойти до распечатанного билета.
Красота здесь служит понятности: движение объясняет, что произошло (куда делся элемент, что изменилось), а не украшает.

### 10.1 Принципы «интуитивно просто»

| Принцип | Как реализуем |
|---|---|
| **Один главный сценарий** | «Выбрал участника → увидел билет → напечатал». Рабочее место открывается сразу на первом участнике (статуса в таблице нет), билет уже нарисован, кнопка «Печать» — единственная акцентная |
| **Одно основное действие на экран** | Одна primary-кнопка, остальное вторично; одинаковое расположение действий на всех экранах |
| **Постепенное раскрытие** | Сложное (настройки проекта, роли и права) — на отдельных экранах; на рабочем месте только нужное |
| **Понятный язык** | Без жаргона: «Печать выбранных», «Отменить»; ошибки говорят, что делать («Нет связи — сохраним, как только появится») |
| **Отмена вместо подтверждений** | Строки не удаляются, а очищаются (имя и телефон; строка и номер остаются) — тост «Очищено 3 строки · **Отменить**» (8 с, Undo возвращает текст пакетной правкой). Модальное подтверждение — только для необратимого (удалить проект — ввод названия) |
| **Мгновенный отклик** | Оптимистичные обновления, отклик на нажатие < 100 мс, скелетоны вместо «пустого экрана», индикатор прогресса на долгих операциях (печать/сохранение пачки) |
| **Привычные паттерны** | Таблица как в Excel: стрелки, Enter, Tab, Esc, F2, ⌘/Ctrl+C; **вставка блока текста/ячеек из Excel** заполняет выделенные ячейки сверху вниз (лишние строки идут ниже выделения, новые строки создаются только в конце таблицы; одно значение заполняет все выделенные ячейки; две колонки — имя и телефон), одним пакетным запросом, тост «Вставлено N строк, начиная с № K» с «Показать» и «Отменить»; выделение мышью: клик, Shift+клик, Ctrl/Cmd+клик, протяжка с автопрокруткой у края, Ctrl+A; поиск находит и по номеру строки; телефон — свободный текст без проверок; drag&drop картинки в настройках; подсказки горячих клавиш в тултипах |
| **Скрываем недоступное по правам** | Нет права — элемента нет (нет шума). Недоступно по состоянию — отключено **с объяснением** («Проект завершён — только просмотр») |
| **Пустые состояния с действием** | «Проектов пока нет» + понятный следующий шаг (создать / обратиться к администратору) |
| **Подсказки в нужный момент** | 2–3 ненавязчивых подсказки при первом использовании (закрываются навсегда) вместо длинных инструкций |
| **Единообразие** | Одни компоненты, иконки, тексты и поведение везде; дизайн-система из токенов |

### 10.2 Система движения (motion tokens)

| Токен | Значение | Где |
|---|---|---|
| `--dur-press` | 80 мс | Нажатие кнопок (`:active`, scale .98) |
| `--dur-fast` | 140 мс | Hover, переключатели, смена вкладок, crossfade билета |
| `--dur-base` | 220 мс | Меню, попапы, модалки (появление), тосты |
| `--dur-slow` | 360 мс | Смена экрана, перестановка списков, раскрытие панелей |
| `--ease-standard` | `cubic-bezier(.2, 0, 0, 1)` | Перемещения и изменение размеров |
| `--ease-in` / `--ease-out` | `cubic-bezier(0,0,0,1)` / `cubic-bezier(.3,0,1,1)` | Появление / исчезновение (уход быстрее прихода) |
| `--spring` | stiffness 420, damping 34 | Drag, snap плейсхолдера, «отскок» |

Правила: анимируем **только `transform` и `opacity`** (без layout-свойств); ничего дольше 400 мс; stagger ≤ 30 мс на элемент и не более 8 элементов;
`prefers-reduced-motion: reduce` заменяет перемещения мгновенной сменой или fade; движение никогда не несёт смысл в одиночку (статус дублируется текстом/иконкой).

### 10.3 Каталог анимаций и интерактивности

| Где | Что происходит |
|---|---|
| **Вход** | Карточка плавно «всплывает» (fade + 8 px), фон — медленный дрейф градиента (CSS, на паузе при reduced-motion); неверный пароль — короткая «встряска» поля + подсветка; кнопка «Войти» → спиннер → галочка; «показать пароль» — морф иконки |
| **Проекты** | Карточки появляются каскадом; hover — подъём на 2 px, подсветка рамки, мягкое проявление «Открыть»; карточка «Создать» — «плюс» поворачивается; переход между «Активные/Завершённые» и фильтрация поиском — плавная перестановка (FLIP); меню ⋮ — scale из точки нажатия |
| **Рабочее место** | Свернуть/развернуть панель — плавное изменение сетки; смена участника — **crossfade билета** (старое изображение остаётся, пока рисуется новое — без мерцания); новая строка — подсветка цветом автора 1,2 с + slide-in; удаление — схлопывание высоты + fade; **занятая строка:** рамка цвета редактирующего плавно проявляется (fade + лёгкий scale, 140 мс) и так же гаснет при освобождении, подсказка «Редактирует Азам» с аватаром появляется при наведении за 120 мс (на touch — по касанию), попытка править занятую строку — «встряска» рамки; аватары онлайн появляются/уходят с масштабом, соседи плавно сдвигаются; **курсоры других** плавно скользят по строкам (`transform` 120 мс); пачечная печать/сохранение — полоса прогресса на тулбаре |
| **Настройки проекта** | Плейсхолдер следует за пальцем/курсором 1:1, при отпускании — лёгкий snap и пружина, направляющие по центру/краям проявляются за 140 мс; вкладки «Номер/Имя/Телефон» — подчёркивание-«ползунок»; правка шрифта/размера — превью обновляется **мгновенно, без анимации** (отзывчивость важнее); «Сохранить» → галочка |
| **Админ-панель ролей** | Включение права каскадно добавляет зависимые — они подсвечиваются на 600 мс с подписью «добавлено автоматически»; счётчик прав роли «перекатывается»; удаление роли/пользователя — схлопывание строки |
| **Модалки, попапы, тосты** | Модалка: scale .96→1 + fade, фон — fade + лёгкое размытие; тост: slide-up + полоска времени, «Отменить» видна до конца |
| **Переходы между экранами** | View Transitions API там, где поддерживается (Chrome, Firefox, Safari 18+), иначе fade 140 мс; шапка не перерисовывается; чанки следующего экрана подгружаются по hover/focus на ссылку. Только десктоп с мышью (телефоны и планшеты — лёгкий fade), при «меньше движения» — без анимации. Виды: **список ↔ проект** — карточка проекта разворачивается в рабочее пространство (общий элемент `hero`: карточке на время перехода ставится `data-hero`, корню — `data-morph`) и сворачивается обратно в свою карточку; **проект ↔ настройки** — настройки выезжают как лист поверх рабочего пространства (оно отступает и тускнеет), закрытие — в обратную сторону; **соседние экраны** (админка, профиль) — перекрёстный «глубинный» fade с лёгким масштабом и размытием. Длительность — токен `--dur-slow` (360 мс), кривые — токены `--ease-standard`/`--ease-in`; анимируются только transform/opacity/filter и размер снимка-группы (без перерасчёта вёрстки). Логика в `lib/viewTransition.ts`, стили в `styles/base.css` |
| **Листание билета** | В режиме «только картинка» стрелки клавиатуры и кнопки «предыдущий/следующий» переворачивают билет как карточку: старый уходит в сторону движения с лёгким поворотом rotateY и затуханием, новый приходит с противоположной стороны (WAAPI на двух холстах `TicketPanel`, 260/340 мс, только transform/opacity). Быстрые нажатия отменяют текущий поворот, а не выстраиваются в очередь; при «меньше движения» билет меняется мгновенно |
| **Ожидание** | Скелетон (shimmer) показывается, только если загрузка дольше 200 мс (нет «мигания»), и держится не менее 300 мс |

### 10.4 Технические решения

* **CSS в первую очередь:** transitions/keyframes и `@starting-style` для появления, `view-transition-name` для переходов (feature-detect `document.startViewTransition`).
* **Layout- и presence-анимации** (FLIP-перестановки, exit-анимации, пружины, drag) — библиотека **`motion`** (бывш. Framer Motion) в режиме `LazyMotion` с `domAnimation`, подгружается лениво;
  бюджет на анимационный код ≤ 20 КБ gzip внутри общего бюджета (раздел 8) — фактический размер проверяем замером в Фазе 0.
* **Производительность:** цель 60 fps на iPhone среднего класса; `will-change` только точечно и временно; строки виртуализированной таблицы анимируются лишь при вставке/удалении, а не при появлении во вьюпорте;
  рендер билета на canvas разбивается на кванты (`scheduler.yield`/`requestIdleCallback`) и не блокирует анимации.
* **Touch и iOS:** отклик 80 мс, hover-эффекты только в `@media (hover: hover)`, без задержки 300 мс, drag через Pointer Events, анимации учитывают safe-area и появление клавиатуры.
* **Настройка:** переключатель «Меньше анимации» в личном кабинете (поверх системного reduced-motion).
* **Дизайн-система:** токены цвета, типографики и движения + библиотека компонентов (Button, Modal, Menu, Popover, Toast, Skeleton, Table…) с уже встроенной анимацией — экраны собираются из них. При проработке UI используем установленный плагин `frontend-design`.

### 10.5 Приёмка UX и качества движения

* **Юзабилити-тест** (Фаза 7): 3–5 операторов и 1–2 админа, без инструкции. Сценарии: войти и сменить временный пароль → найти участника → распечатать 3 билета;
  админ: создать проект, настроить плейсхолдеры, завести роль и пользователя. Цели: новичок печатает первый билет **< 60 с**, ≥ 90 % задач без помощи, SUS ≥ 80, нет «тупиковых» ошибок.
* **Плавность:** профилирование Chrome/Safari Web Inspector — нет кадров > 50 мс при открытии проекта, скролле 5 000 строк, вставке строк, перетаскивании плейсхолдера, пачечной печати.
* **Тесты:** Playwright-снимки с отключёнными анимациями (стабильность), отдельные сценарии для `prefers-reduced-motion`; проверка, что состояния понятны и без анимации.

## 11. Языки и темы

### 11.1 Языки: русский и узбекский

* Языки: `ru` (по умолчанию) и `uz` (узбекский, **латиница** — официальный алфавит; кириллическую версию при необходимости добавим позже как отдельную локаль). Выбор — в профиле, «Внешний вид → Язык»;
  хранится в `users.locale`, действует на всех устройствах пользователя. До входа (экран логина) язык берётся из `localStorage`/`navigator.language`, иначе русский.
* **Реализация:** типобезопасные словари `i18n/ru.ts` (эталон) и `i18n/uz.ts`; CI проверяет, что в `uz` нет пропущенных ключей. Без тяжёлой библиотеки: числа, даты и списки — через `Intl`
  (`ru-RU`, `uz-Latn-UZ`), плюрализация — `Intl.PluralRules` (в русском формы one/few/many/other, в узбекском one/other). Словарь грузится лениво (несколько КБ gzip),
  переключение — без перезагрузки страницы, с мягким crossfade текста.
* **Что переводится:** весь интерфейс, тексты ошибок (клиент выбирает текст по `error.code`; сервер отдаёт стабильные коды и русский `message` как запасной), подсказки, тосты, названия прав и групп в админ-панели
  (по коду права). **Не переводится:** введённые пользователями данные (имена, названия проектов, названия ролей, созданных админом) и надписи на билете.
* **Шрифты:** подмножества `cyrillic`, `latin` и `latin-ext` — для узбекской латиницы нужны `oʻ`, `gʻ` (U+02BB/U+02BC) и апостроф. Шрифты билета (Montserrat, Roboto, Open Sans, Inter, PT Sans, Oswald,
  Playfair Display, Arimo) проверяем на наличие этих глифов в Фазе 4; у шрифтов без них в списке выбора показывается пометка.
* **Качество:** перевод выполняет или проверяет носитель языка; терминология («проект», «участник», «билет», «роль») — в `docs/glossary.md`; фразы не склеиваем из кусков (порядок слов разный).
  Узбекские строки местами длиннее русских на 10–20 % — вёрстка не должна ломаться (проверка снимками на обоих языках).

### 11.2 Темы: тёмная (по умолчанию) и светлая

* Три режима в профиле: **«Тёмная» (по умолчанию)**, «Светлая», «Как в системе»; хранится в `users.theme`. До входа — `localStorage`, иначе тёмная.
* **Реализация:** все цвета — CSS-токены в двух наборах (`:root[data-theme="dark"]`, `[data-theme="light"]`); атрибут выставляется inline-скриптом **до первой отрисовки** (нет «вспышки» чужой темы);
  `color-scheme` и `<meta name="theme-color">` меняются вместе с темой (цвет строки состояния iOS/Android). Переключение — плавный кроссфейд 220 мс через токены (при `prefers-reduced-motion` — мгновенно).
* **Дизайн:** макет утверждён только в тёмной теме, поэтому светлую палитру проектируем по тем же токенам и показываем на согласование до реализации. Требования: контраст WCAG AA (≥ 4,5:1 для текста, ≥ 3:1 для границ,
  иконок и обводок); цвета пользователей (обводка занятой строки, курсоры, аватары) проверяются на обоих фонах и при необходимости подправляются по яркости.
* Билет (canvas) от темы не зависит; бумага для печати всегда светлая.
* **Тесты:** снимки Playwright ключевых экранов в 2 темах × 2 языках, автоматическая проверка контраста.
